# 设计决策记录

## 为什么「先分区域、再识别内容」

端到端模型要同时学「哪里是表格」和「表格里是什么」，评测时两个错误耦合在一起，
不好定位。拆成两段后，region_accuracy 单独衡量版面，cell_accuracy 单独衡量内容，
指标可解释、可回归。

## 为什么约束解码而不是「生成后 parse」

生成后 parse 的失败率随输出变长而上升（一个括号没配平就全盘崩溃）。约束解码把
合法性保证前移到生成过程，`json_structure_f1` 恒为 1.0。真实部署用 grammar 约束
（Outlines / XGrammar），本仓库的有限状态机是它的极简原理参考。

## 为什么 mock 训练信号必须「单调趋 1」

如果「对 +1 错 -1」，skill 低时正确率 < 50%，期望漂移为负，skill 会被压到 0。
改成 delta 恒正，skill 单调爬向 1.0，收敛曲线干净（历史项目反复踩过这个坑）。

## 为什么 boost 在 skill=0.5 时恰为 0

`boost=(skill-0.5)*2` 让 skill=0.5 对应「纯随机」基线（recall ≈ 1/n），而不是
「半对」。否则 skill=0.5 就已经 68%+ 正确，训练起点虚高，看不出提升。

## 为什么共享 oracle

mock 后端和评测框架若各自随机，会出现「指标涨了但不知道是模型还是评测的锅」。
共享同一组 `oracle_*(doc_id, idx, ...)` 派生函数后，`skill=1.0` 必然满分，数字可信。
